# Documentation harness

Repository-wide instructions in `../AGENTS.md` also apply here.

- Start with `README.md` to find existing knowledge before adding a document.
- Keep the index and incoming links current when moving or adding documents.
- Store experiment evidence and detailed research under `experiments/`; index postponed ideas and undecided proposals in [../ROADMAP.md](../ROADMAP.md), with stable IDs, outcome, horizon, decision status, dependencies and source links. Preserve the distinction between proposals and approvals; a successful experiment does not mark a product feature as shipped.
- Give findings and brainstorming topics short stable IDs so they can be referenced later.
- Record reproducible methods, source attribution and relevant constraints. Keep secrets, machine-specific absolute paths, private conversations and local artifacts out of tracked docs.
- Prefer updating an existing topic over duplicating it. Keep the root harness concise and link to detailed knowledge here.
